# 自分専用 AI アシスタント UI 設計書

作成日: 2026-10-10

## 1. 目的

Claude Code のエンジン(Claude Agent SDK)をラップした、自分専用のローカル Web アプリを作る。
研究支援(卒業研究: PDR・屋内測位)と開発支援を重点とし、専用のコンパクトなメモリを持ち、
使うほど自分の文脈を覚えて賢くなる(自己強化)ことを目指す。

参考: Reddit r/ClaudeCode の投稿「Claude のコードをラップした AI アシスタント UI」。

## 2. スコープ

### 含む(最初の版)
- ブラウザ(localhost)で使えるチャット画面
- Markdown ファイルによるメモリ(読み込み・追記・取り消し)
- 許可したローカルフォルダの読み取り(ファイル閲覧・検索)

### 含まない(YAGNI)
- ベクトル検索・データベース
- メモリの自動整理(まず手動)
- Git / GitHub / Notion / Web 検索との接続(後から追加)
- 認証・複数ユーザー対応(自分専用の localhost のみ)

## 3. 全体構成

```
ブラウザ (localhost:8000)
   │  メッセージ送信 / 応答をストリーミング受信
   ▼
Webサーバー (Python + FastAPI)
   │  セッション管理 / メモリ読み込み / Claude 呼び出し
   ▼
Claude Agent SDK (Claude Code エンジン)
   │  ファイル読み書き・検索
   ▼
ローカルのファイル群
   ├─ memory/        アシスタント専用の記憶(Markdown)
   └─ 許可した研究・開発フォルダ(読み取り専用)
```

### 部品

| 部品 | 役割 | 依存先 |
|---|---|---|
| `server.py` | HTTP とストリーミングの入口 | `agent.py` |
| `agent.py` | Agent SDK の呼び出し。システムプロンプトにメモリを注入 | `memory.py` |
| `memory.py` | `memory/*.md` の読み込み・追記・目次更新 | ファイルのみ |
| `static/index.html` | チャット画面(ビルド不要の1ファイル) | `server.py` |
| `config` | 読み取りを許可するフォルダの一覧 | なし |

言語は Python に統一する(研究コードが Python のため)。

## 4. メモリの仕組み

### 構造

```
memory/
├─ INDEX.md          目次。1行1項目(ファイル名 + 要約)。毎回読み込む
├─ profile.md        自分について(専攻、好み、返答のスタイル)
├─ projects/
│   ├─ pdr-research.md   卒業研究の背景・決定事項・未解決の課題
│   └─ ...
└─ lessons.md        訂正や失敗から得た次回の注意点
```

### 読み込み
1. 毎回 `INDEX.md` と `profile.md` だけをシステムプロンプトに入れる
2. 話題に関係する `projects/*.md` は、Claude が必要と判断したときだけ読む
3. メモリが増えても毎回の読み込み量は増えない

### 自己強化
- 会話の終わりに「新しく分かったこと・決まったこと・訂正されたこと」を抽出し、追記案を作る
- ユーザーが承認すると該当ファイルに追記する。取り消しもできる
- ユーザーの訂正内容は `lessons.md` に記録し、次回以降に反映する

### 安全面
- 書き込みは `memory/` 配下のみ。研究・開発フォルダは読み取り専用
- 追記は画面に表示し、承認制にする
- すべて Markdown なので、エディタで直接修正できる

## 5. データの流れ

1. ブラウザからメッセージを送信
2. `server.py` が受信し、`memory.py` で `INDEX.md` と `profile.md` を読む
3. `agent.py` がシステムプロンプトに入れ、Agent SDK を呼ぶ
4. 応答をストリーミングで表示。ファイル読み取りや検索の動作もそのつど表示
5. 返答後、記憶に残すべきことがあれば追記案を表示
6. ユーザーが承認または取り消し。承認されたら `memory/` に書き込む

## 6. エラー処理

| 状況 | 動作 |
|---|---|
| Claude 呼び出しの失敗(認証切れ・ネットワーク) | 画面にエラー表示。会話は壊さず再送できる |
| 許可外フォルダの読み取り | SDK の権限設定で拒否し、理由を表示 |
| `memory/` が空または壊れている | 空のテンプレートで起動し、警告のみ出す |
| 応答が長時間止まる | タイムアウトして中断ボタンを表示 |

## 7. テスト

- `memory.py`: 読み込み・追記・目次更新の単体テスト(最重点)
- `agent.py`: SDK 呼び出しを差し替え可能にし、システムプロンプトに記憶が入ることを確認
- 全体: サーバーを起動し、ブラウザで1往復して「記憶が追記され、次の会話で使われる」ことを手動確認

## 8. 実装の順番

1. `memory.py` とそのテスト
2. `agent.py`(コマンドラインで1往復できる状態)
3. `server.py` と `index.html`(画面で会話できる状態)
4. 記憶の追記承認 UI

## 9. 前提と実装時の確認事項

- Claude Agent SDK(Python)の具体的な API・認証方法・権限設定の書き方は、実装開始時に公式ドキュメントで確認する
- 認証は、API キーまたはサブスクリプションのどちらを使うかを実装時に決める
